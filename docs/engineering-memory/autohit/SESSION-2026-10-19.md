## ProtoHax reference

The ProtoHax UserScript API models a connected session, entity state, server-side rotation and queued protocol/entity interactions. Its `interactEntity(..., "attack")` helper is session/protocol-backed; it cannot be copied directly into the in-process C++ client without implementing a compatible protocol/session path. The useful architectural lesson is to synchronize target identity, server-side rotation and attack action at the correct tick, not to copy the call literally.

References:
- https://userscript.protohax.net/
- https://userscript.protohax.net/api/events-and-packets/
- https://github.com/Mojang/bedrock-protocol-docs

## Input binding proposal

- Existing Bedaim module keybind is a module activation/toggle binding; it is not the Minecraft attack control.
- Current AutoHit activates when enabled and does not require a keyboard/mouse binding.
- A user-configurable attack binding can only be useful if the runtime exposes the actual configured game input or a safe input-dispatch interface. No proven in-process touch/attack-input injection API has been identified in the inspected source yet.
- Do not add a fake “press attack key” mode that simply calls the same unverified native route or injects an ordinary keyboard key unrelated to mobile touch controls. First find a supported game input action API and a way to verify that it generates the same server-visible attack as a manual attack.
