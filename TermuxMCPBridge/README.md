# Termux MCP Bridge — Alpha 0.2

Native Android app hosting an authenticated MCP Streamable HTTP endpoint on `127.0.0.1:8765/mcp`.

## Implemented
- Black/dark device dashboard with quick actions.
- Device diagnostics: model, Android/API level, chipset, battery, RAM, internal storage and network transport.
- Launch shortcuts for Termux and Shizuku, Shizuku permission request, root capability probe and Android settings shortcuts.
- Local MCP foreground service and authenticated loopback endpoint.
- Per-install 256-bit bearer token, masked by default, with copy and rotation controls.
- MCP workspace tools: `bridge_status`, `workspace_list`, `workspace_read`, `workspace_write`.
- APK Lab: import a user-selected APK, parse package/version/SDK metadata, list requested permissions and sensitive permissions, inventory app components, enumerate ZIP contents, count DEX/native libraries/resources/assets and calculate signer certificate SHA-256 fingerprints. It can safely extract the raw ZIP archive with path traversal and decompression-size limits.
- APK file backup/duplication inside the app-private workspace, raw archive extraction and export through Android document picker. Duplication preserves the original bytes and does not modify package identity or signature.
- File access restricted to app-private workspace with path traversal checks and size limits.

## Not yet implemented
- Full Apktool-style binary XML/resource decoding and decompilation; current extraction is raw ZIP extraction, not resource decompilation.
- Repackaging or package-identity cloning. APK Lab currently inspects and backs up APK files without altering their signatures.
- Termux command execution, process manager and build orchestration.
- Shizuku-backed file/process operations beyond current permission/capability checks.
- Cloudflare Tunnel and remote ChatGPT connectivity.
- Root command execution.

## Persistent update signature
The Android debug keystore generated by GitHub-hosted runners is ephemeral. To make future APKs install as in-place updates, configure these GitHub Actions repository secrets:
- `BRIDGE_SIGNING_KEYSTORE_BASE64`: base64 content of a private JKS/PKCS12 keystore.
- `BRIDGE_SIGNING_STORE_PASSWORD`: keystore password.
- `BRIDGE_SIGNING_KEY_ALIAS`: signing key alias.
- `BRIDGE_SIGNING_KEY_PASSWORD`: key password.

The workflow uses that same keystore for every debug APK once all four secrets are configured. Keep a secure offline backup of the keystore and passwords. Never commit the keystore or passwords to the repository. Until configured, CI warns that the artifact uses an ephemeral debug key and cannot guarantee in-place updates. The already-installed earlier APK was signed with an ephemeral runner key, so a one-time uninstall/reinstall may be required when switching to the persistent key.

## Build
JDK 17, Android SDK platform 36 and build-tools 36.0.0. Run `gradle :app:testDebugUnitTest :app:assembleDebug`.

## Security
No arbitrary shell is exposed. Do not share the bearer token. The listener remains bound to loopback; remote access is disabled until tunnel lifecycle and authentication are tested.
